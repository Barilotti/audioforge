# ADR-0001: Стек C++20 + JUCE 8 + CMake, интерфейс на JUCE

- **Статус:** принято
- **Дата:** 2026-11-18
- **Связано:** архитектура v0.2, разделы 3.1–3.3, 10

## Контекст
AudioForge — настольное приложение для Windows 10/11 с real-time аудиодвижком. ТЗ предлагает Qt/C++ или PySide6 для UI, JUCE для аудио, NumPy/librosa для анализа, libsndfile для форматов.

## Решение
- Язык C++20, компиляторы MSVC 2022 (Windows) и Clang (Linux CI).
- JUCE 8 для UI, аудиоустройств, форматов и DSP. Qt не используется.
- Сборка CMake, зависимости через CPM.cmake с фиксированными версиями.
- Анализ на C++ (без Python-рантайма), для ML в будущем — ONNX Runtime.
- Декодеры JUCE за интерфейсом `IAudioDecoder` вместо libsndfile.
- Зависимости только с разрешительными лицензиями (MIT/BSD/BSL/public domain).
- На время разработки — бесплатный коммерческий уровень JUCE (Starter) и WASAPI; лицензионные вопросы закрываются по списку перед релизом (раздел 10).

## Последствия
- Один цикл событий и одна система окон; нет стыковки двух фреймворков.
- Docking-панели придётся писать самим (в Phase 1 — резиновые панели и Layout Presets).
- Ядро не зависит от GUI, поэтому смена UI-фреймворка в будущем затронет только `af_ui`.

## Рассмотренные альтернативы
Qt + JUCE (два цикла событий, LGPL/коммерческий Qt), PySide6-прототип (не проверяет real-time движок), librosa (Python-рантайм в установщике).
