# ADR-0003: RenderGraph и обмен данными между потоками

- **Статус:** принято
- **Дата:** 2026-11-18
- **Связано:** архитектура v0.2, разделы 4.1–4.3

## Решение
- Движок получает неизменяемый `RenderGraph`, скомпилированный из снимка документа. Модель напрямую аудиопоток не читает.
- Цепочка владения: компилятор → message thread → почтовый ящик (`std::atomic<RenderGraph*>`, «новейший побеждает») → аудиопоток → RetireQueue (SPSC, 64) → message thread → удаление.
- В аудиопотоке запрещены аллокации, освобождение памяти (в том числе последнего `shared_ptr`), мьютексы, ожидание, I/O, логирование, исключения.
- Переполнение: почтовый ящик не переполняется; при заполненной RetireQueue подмена откладывается (`deferredSwaps`); параметры — `ParameterBank` с последним значением; команды транспорта повторяются UI; события RT→UI отбрасываются со счётчиком.
- Состояние DSP хранится в `NodeStateStore` по стабильным `NodeId` и переживает перекомпиляцию; структурные правки в зоне воспроизведения подменяются кроссфейдом 256 сэмплов.
- Закрытие проекта и выход из приложения — по последовательностям раздела 4.2 (пустой граф, подтверждение `appliedGeneration`, остановка устройства, отмена задач).

## Последствия
- RTSan в Linux CI и debug-проверка аллокаций на Windows обязательны с этапа S1.
- Тесты переполнения каждого канала и тест запуска/выхода в CI.
