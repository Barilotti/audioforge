# ADR-0006: Ассеты в памяти, AudioBufferCache и бюджеты памяти (D11)

- **Статус:** принято с уточнением
- **Дата:** 2026-11-18
- **Связано:** архитектура v0.2, раздел 4.7

## Решение
- Phase 1: ассет целиком декодируется в float32 с родной частотой файла. Только 64-битная сборка.
- Лимиты по умолчанию (все настраиваются):
  - размер одного ассета после декодирования ≤ 1 ГБ, предупреждение после 256 МБ;
  - **мягкий бюджет** кэша `min(40% физической RAM, 80% жёсткого бюджета)` — выше него вытесняются неиспользуемые ассеты;
  - **жёсткий бюджет** `min(50% физической RAM, 8 ГБ)` — новые импорты отклоняются;
  - **резерв системной памяти** `max(1 ГБ, 10% RAM)` — перед каждым декодированием проверяется доступная память системы (`GlobalMemoryStatusEx`); если после выделения останется меньше резерва, импорт откладывается или отклоняется даже при свободном бюджете AudioForge.
- По системному уведомлению о нехватке памяти (`CreateMemoryResourceNotification`) вытесняются все вытесняемые буферы.
- `bad_alloc` при декодировании ловится на worker; ассет переходит в Failed, приложение продолжает работу.
- Закреплены ассеты текущего документа и живых графов; остальные вытесняются по LRU. Освобождение памяти — никогда на аудиопотоке.
- Воспроизведение не ждёт декодирования; клип без готового ассета звучит тишиной и показывает индикатор загрузки.
- Потоковое чтение с диска — Phase 2–3, за тем же интерфейсом `ISampleSource`.

## Уточнение (решено 2026-11-18)
На машинах с 20 ГБ RAM и больше оба бюджета по исходной формуле были равны 8 ГБ, и вытеснение начиналось одновременно с отказом в импорте. Решение Nick: мягкий бюджет не выше 80% жёсткого, то есть `min(40% RAM, 80% жёсткого)`. При 8 ГБ жёсткого вытеснение начинается с 6,4 ГБ. На машинах до 20 ГБ RAM формула даёт те же 40% RAM, что и раньше. Реализовано в `assets/MemoryBudget` (S1.3).
