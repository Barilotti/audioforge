# ADR-0010: Структура сборки и зависимостей

- **Статус:** принято
- **Дата:** 2026-11-18
- **Связано:** ADR-0001, архитектура v0.2 раздел 2; реализовано в S0.1–S0.5

## Контекст
Модули AudioForge (`af_core` … `af_ui`) — отдельные CMake-цели. JUCE поставляет модули как INTERFACE-библиотеки: каждая цель, которая их линкует, заново компилирует исходники JUCE. Это дублирует код и ломает линковку.

## Решение
- **Все модули JUCE компилируются один раз в статическую библиотеку `af_juce`.** Наши цели линкуют `AudioForge::juce`, а не `juce::` цели напрямую. Заголовки JUCE подключаются как системные (`SYSTEM`), поэтому строгие предупреждения AudioForge (`-Werror`, `/W4 /WX`) не срабатывают внутри JUCE.
- **Конфигурация JUCE задаётся централизованно** в `cmake/Dependencies.cmake`: ASIO выключен до решения L2, WASAPI включён, DirectSound и JACK выключены, MP3 выключен до S10, модальные циклы запрещены, веб-браузер и curl не используются.
- **Версии зависимостей зафиксированы** (CPM.cmake лежит в репозитории): JUCE 8.0.17-security, Catch2 3.16.1. Обновление — отдельным PR.
- **JUCE — приватная зависимость `core`:** публичные заголовки `core` содержат только стандартные типы. `model`, `serialization` не видят JUCE вообще.
- **Правила зависимостей проверяются тестом** `architecture.module_includes`: запрещённый `#include` между модулями ломает CI.
- **Статический C++ runtime MSVC** (`/MT`): установщику не нужен VC++ Redistributable.
- **Установщик — Inno Setup 6**, собирается и проверяется (тихая установка, запуск, удаление) в CI.
- **CI** (GitHub Actions): clang-format; Linux Clang Debug/Release и GCC Debug с тестами; clang-tidy; RealtimeSanitizer (Clang 20) с тестом-«канарейкой»; Windows MSVC Debug/Release с тестами, установщиком и артефактами.

## Последствия
- Новый модуль JUCE добавляется в одном месте (`af_juce`).
- Запуск GUI-тестов на Linux требует `xvfb-run`.
- При переходе на MSIX или подпись кода (L5) меняется только шаг упаковки.

## Рассмотренные альтернативы
Линковать `juce::` модули в каждую цель (дублирование кода JUCE); динамический CRT (`/MD`) с VC++ Redistributable в установщике (лишний шаг установки и обновлений); WiX/MSIX вместо Inno Setup (сложнее для первой версии, возможен переход позже).
