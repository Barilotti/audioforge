# ADR-0012: Декодирование WAV и AudioBufferCache

- **Статус:** принято
- **Дата:** 2026-11-18
- **Связано:** ADR-0006, архитектура v0.2 раздел 4.7; реализовано в S1.3

## Контекст
Phase 1 импортирует WAV во всех вариантах, которые встречаются у звукорежиссёров: PCM 8/16/24/32, float 32/64, WAVE_FORMAT_EXTENSIBLE (многоканальные рекордеры), BWF, а также RF64/BW64 и Wave64 для файлов больше 4 ГБ. В разделе 4.7 поддержка RF64/W64 была помечена «проверяем на этапе S1». Декодер JUCE читает RF64, но не Wave64, и его сообщения об ошибках не различают «битый файл» и «неподдерживаемый формат».

## Решение
- **Собственный парсер WAV** (`assets/WavDecoder`) без JUCE: RIFF/WAVE, RF64 и BW64 (ds64), Wave64 (GUID-чанки, выравнивание 8 байт). Формат определяется по содержимому, а не по расширению (`DecoderRegistry`).
- **Ошибки с причиной:** `notFound`, `ioError`, `invalidData` (битый файл: нет fmt/data, неверное выравнивание блока, обрезанный заголовок), `unsupported` (RIFX, ADPCM/A-law/µ-law, больше 32 каналов, неподдерживаемая частота).
- **Обрезанный data-чанк** (рекордер потерял питание) не ошибка: декодируются имеющиеся кадры, `AudioFileInfo::dataTruncated` позволяет UI предупредить пользователя.
- **Wave64 и `fact`:** некоторые программы (ffmpeg) записывают в размер data-чанка выравнивание; если есть чанк `fact`, длина берётся из него.
- **Фикстуры** созданы ffmpeg (`tests/data/wav/generate.py`), то есть независимым кодировщиком, и проверяются посэмплово. Повреждённые варианты тесты получают правкой байтов фикстур.
- **AudioBufferCache:** фоновые потоки декодирования; состояния unloaded → decoding → ready → evicted, decoding → failed с повтором; отмена; бюджеты ADR-0006 (лимит одного ассета 1 ГБ, мягкий и жёсткий бюджеты, резерв системной памяти); вытеснение незакреплённых по LRU; `std::bad_alloc` переводит ассет в failed. `request()` не блокирует вызывающий поток.

## Последствия
- Пики считаются в том же проходе чтения на этапе, где появится waveform (S2).
- Буфер, который ещё держит граф, освобождается при удалении графа; учёт памяти кэша считает только буферы, которые держит кэш.
- AIFF, FLAC и MP3 добавляются как новые `IAudioDecoder` без изменений кэша.

## Рассмотренные альтернативы
`juce::WavAudioFormat` (нет Wave64, грубые ошибки); libsndfile (LGPL, лишняя зависимость ради одного формата в Phase 1).
