# ADR-0015: Транспорт, импорт файла и мастер-метр (S1.6)

- **Статус:** принято
- **Дата:** 2026-11-18
- **Связано:** ADR-0003, ADR-0013, ADR-0014, архитектура v0.2 раздел 4.2 (таблица каналов), этап S1; реализовано в S1.6

## Контекст
Этап S1 заканчивается сценарием «выбрать устройство, открыть WAV через File → Import, нажать Play, услышать, остановить, видеть master-метр». Нужны команды транспорта в аудиопоток, события обратно, метр без потерь пиков и понятное поведение Stop.

## Решение
- **Команды транспорта** (`engine::TransportCommand`: play, pause, seek) идут через SPSC-очередь на 256 записей, как в таблице 4.2. Аудиопоток применяет все команды из очереди в начале блока, до рендера. `AudioEngine::transport()` возвращает `false`, если очередь полна.
- **`app::Transport`** — сторона message thread. Хранит желаемое состояние (UI показывает его сразу, даже без устройства). Команды, не поместившиеся в очередь, хранятся и отправляются снова в `pump()` (30 Гц). Поскольку все команды из очереди применяются перед одним и тем же блоком, значимы только последнее состояние play/pause и последний seek, поэтому отложенные команды сворачиваются максимум до двух и не растут. Единственный отправитель — `DeviceService::transport()`: при потере устройства транспорт останавливается там же.
- **Поведение кнопок:**
  - Space — Play/Stop, Shift+Space — Play/Pause (как в DAW).
  - Stop возвращает к позиции, с которой начато воспроизведение; Stop в остановленном состоянии — к началу Event.
  - Достижение конца графа (`RenderGraph::endFrame`, конец последнего клипа с учётом ещё не декодированных) останавливает воспроизведение и возвращает к позиции старта. Play в конце начинает с нуля.
- **События RT → UI** (`EngineEvent`, сейчас только `endReached`) идут через SPSC на 256 записей. При переполнении событие отбрасывается и растёт `droppedEvents`. Событие несёт число применённых команд: конец, случившийся до более новых команд пользователя, игнорируется.
- **Мастер-метр** (`engine::MasterMeter`) измеряет итоговый выход каждого блока. Пик копится атомарным максимумом до чтения UI (`read()` забирает и обнуляет), поэтому ни один блок не теряется при любой частоте экрана. RMS — экспонента с постоянной 300 мс. Признак клиппинга (> 0 dBFS) держится до клика по индикатору. Падение пика 20 дБ/с, удержание 1,5 с — на стороне UI (`LevelMeter`).
- **`app::Playback`** решает, что играет: файл из File → Import Audio... (Ctrl+I) или перетаскивания на окно, либо тестовый тон из Audio Settings. Импорт строит проект из одного Event, одного слоя и одного клипа на весь файл; декодирование в фоне через `AudioBufferCache`; предыдущий файл играет, пока новый не готов, и остаётся, если импорт не удался. Граф перекомпилируется при смене формата устройства и когда готов ассет, которого граф ждал.
- **Нагрузка:** строка транспорта показывает загрузку аудиопотока и счётчик dropouts устройства — по ним проверяется критерий «час без xruns на буфере 256».

## Последствия
- Loop, scrub и маркеры добавят новые виды `TransportCommand` без изменения механизма.
- `ProjectSession` с Undo (S2) заменит одно-файловый проект `Playback`; транспорт и метр останутся.
- Метры слоёв (S3) используют тот же `MasterMeter`.

## Рассмотренные альтернативы
- **Только атомики «желаемого состояния» без очереди команд.** Проще, но таблица 4.2 закрепляет SPSC, а loop и scrub потребуют упорядоченных команд. Свёртка в `app::Transport` даёт ту же неспособность переполниться.
- **Triple buffer для метра.** UI читает реже, чем идут блоки, и пропускал бы пики промежуточных блоков.
