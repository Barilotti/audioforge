# ADR-0016: Пики waveform и глобальный кэш пиков (S2.1)

- **Статус:** принято
- **Дата:** 2026-11-18
- **Связано:** ADR-0006, ADR-0012, архитектура v0.2 разделы 4.7 и 5.5; реализовано в S2.1

## Контекст
Таймлайн (S2.2–S2.3) рисует волну клипов при любом зуме и не может каждый раз проходить по сэмплам. Пересчитывать пики при каждом открытии длинного файла долго, а файлы переименовывают и переносят.

## Решение
- **`PeakData`:** min/max каждого блока по 256, 4096 и 65536 кадров, отдельно по каналам, на частоте файла. Каждый уровень — 16 блоков предыдущего; последний блок может быть короче. `range(channel, begin, end)` берёт самый грубый уровень, блоки которого не длиннее диапазона, и покрывает диапазон целыми блоками. Диапазоны короче 256 кадров UI рисует по сэмплам.
- **Один проход:** `PeakBuilder` получает каждый декодированный блок в том же цикле, что и декодер, грубые уровни строятся из нулевого в конце. Аудио, созданное в памяти (`insertDecoded`), тоже получает пики.
- **Ключ — содержимое файла:** XXH3-128 по всем байтам файла (`ContentHash`, xxHash 0.8.3, BSD-2). Считается в начале задания декодирования, только если подключён кэш на диске. Тот же хэш войдёт в fingerprint для Relink (S4.3).
- **Кэш на диске** `PeakCache`: `%LOCALAPPDATA%\AudioForge\Cache\peaks\<hex>.afpk`.
  - Файл: `AFPK`, версия формата, частота, каналы, длина, размеры блоков, данные float little-endian, в конце XXH3-64 всего предыдущего.
  - Запись атомарная: уникальный временный файл и переименование.
  - Несовпадение версии, длины, каналов или контрольной суммы считается промахом, и файл перезаписывается.
- **Раньше декодирования:** если пики нашлись в кэше, `AssetStatus::peaks` заполняется сразу после хэширования (состояние ещё `decoding`), и UI может показать волну, пока звук грузится. Повторно пики не считаются.
- **Вытеснение:** пики остаются в записи `AudioBufferCache`, когда буфер звука вытеснен, чтобы волна не пропадала. Они примерно в 32 раза меньше звука и пока не входят в бюджет памяти.

## Последствия
- Размер папки кэша на диске пока не ограничен; очистка старых `.afpk` по LRU появится вместе с настройками (S8). Папку можно удалить вручную, она восстановится.
- xxHash добавлен в список сторонних лицензий для `THIRD_PARTY.md` (S10.3).
- Хэширование читает файл ещё раз. Для файла из дискового кэша ОС это быстро; для холодного файла добавляет время одного чтения перед декодированием. Если это станет заметно, хэш можно считать параллельно с декодированием.

## Рассмотренные альтернативы
- **Ключ по пути, размеру и времени изменения.** Быстрее, но переименование или перенос файла вызывает пересчёт, а одинаковые файлы в разных местах дублируются.
- **Пики в int16.** Вдвое меньше, но файлы float выше 0 dBFS обрезались бы.
